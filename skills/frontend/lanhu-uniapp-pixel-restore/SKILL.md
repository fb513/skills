# Lanhu Uniapp Pixel Restore

用于把蓝湖设计稿高保真落到本仓库的 uni-app 小程序页面。实现必须以结构化设计证据、项目代码和设计 token 为优先依据；微信小程序截图是工作结束前的验证手段，不是实现前反推页面的主要输入。执行时必须使用当前环境可用的设计读取、资源获取、微信小程序预览、微信小程序截图和验证能力。除本仓库指定的 OSS 上传脚本、已有微信小程序 E2E 自动化能力外，Skill 文档不得绑定具体工具名、命令名或 MCP 调用名。

详细执行细则见 [references/uniapp-pixel-restore.md](references/uniapp-pixel-restore.md)。实现前只读取与当前任务相关的部分；如果没有可用的设计读取、资源获取或截图能力，按本文的降级规则交付风险说明。

## 不可违反

- 不得直接复制设计工具导出的整页绝对定位骨架、逐层坐标、无语义 DOM、固定堆叠层级或为贴图生成的容器。
- 不得把设计导出的 HTML 结构当成最终页面结构；它只能作为视觉规格、资源裁剪和结构推断证据。
- 不得使用临时远程资源、失效外链、emoji、临时 SVG 或明显占位内容冒充设计资源；最终页面只能引用稳定 OSS 资源或项目既有资源。
- 不得在明显视觉偏差未归因、未修正、未复查时结束任务。
- 不得为了对齐单一截图滥用负间距、无语义位移、固定坐标或页面级定位。
- 不得只还原页面内自定义导航而遗漏 `src/pages.json` 页面配置；`navigationBarTitleText`、`navigationStyle`、`backgroundColor` 等页面级配置必须与设计标题、导航形态和页面底色同步。
- 不得把小程序截图当成设计稿本身来反推规格；截图只能在代码实现和静态核对完成后用于收尾验证、发现偏差和补充归因。

## 强制流程

1. 执行前检查：确认设计读取、资源获取、OSS 上传脚本、目标页面路由、`src/pages.json` 配置和小程序 E2E 能力是否可用，并记录缺失能力的降级方案。
2. 获取设计证据：取得画布尺寸、页面层级、HTML/CSS 或等价结构化标注、Design Tokens、设计截图和切图资源清单。
3. 建立规格账本：记录页面背景、顶部区域、模块边界、组件尺寸、文本规格、颜色、间距、圆角、阴影、渐变、图片裁剪、状态差异、设计值到小程序实际值的换算结果和资源来源。
4. 资源处理：独有位图、照片、插画、复杂背景和设计专属切图下载后必须使用 `scripts/upload-image-to-oss.cjs` 上传到 OSS，并记录本地源文件、脚本输出的 OSS `url`、尺寸和使用位置；已有 `FyIcon` 或项目既有资源能高保真表达的语义图标优先复用，并在规格账本记录替代依据。
5. 推导语义布局：从坐标和层级中推断模块、列表、按钮、Tab、卡片、角标、浮层、图片裁剪和状态，而不是复制导出结构。
6. 实现并静态核对页面：遵守本仓库 Vue 3、uni-app、TypeScript、Tailwind token、中文文案、图标体系、导航封装和资源路径约定；同时更新 `src/pages.json` 中目标页面的 `navigationBarTitleText`、`navigationStyle`、`backgroundColor` 等页面级配置，并先完成代码、资源、页面配置和 token 映射核对。
7. 小程序收尾验证：代码实现和静态核对完成后，默认使用本仓库已有微信小程序 E2E 自动化能力进行构建、打开、路由进入目标页、截图和视觉复查；H5 只能在小程序自动化不可用时作为降级辅助，不能替代小程序验收结论。
8. 偏差闭环：发现偏差时先归因，再修正并重新验证受影响项。
9. 交付说明：说明完成项、验证方式、无法验证项、设计取舍和剩余风险。

## 证据优先级

1. HTML/CSS 或等价结构化标注中的视觉属性值是主要规格来源。
2. Design Tokens 只补足 CSS 或标注缺失的渐变、边框、阴影、透明度等细节。
3. 设计截图和小程序截图用于视觉复核，不能覆盖明确的结构化规格值，也不能替代项目代码和设计 token 判断。
4. 现有项目 token 优先用于常规页面规范；颜色、阴影、圆角和字号先映射到 `DESIGN.md`、`tailwind.config.js`、`src/styles/design-tokens.scss` 中的 token。
5. 像素还原关键值没有等价 token 时，允许页面局部样式使用换算后的设计精确值；颜色值必须优先用页面局部 CSS 变量承接，避免裸 `#hex` / `rgb(a)` 散落在业务样式中，并在规格账本记录原因。

## 单位与布局

- 先确认设计画布宽度，再把设计 px 按目标小程序宽度换算为 rpx；不要未经确认套用经验比例。
- 375px 设计画布才可等价使用 `px × 2 = rpx`；其他画布必须使用 `px × 750 / 画布宽度`，并在规格账本记录换算比例。
- 关键宽高、间距、字号、行高、圆角、阴影和图片裁剪都必须能追溯到设计证据，并写出设计值、换算公式、目标 rpx 值、最终代码值。
- 页面必须适应真实机型、动态内容、安全区和业务状态。
- 只有浮层、角标、吸顶、遮罩、动画、图片裁剪、组件限制等有明确语义的元素，才可以使用定位、层级、位移、固定尺寸或裁剪。

## 验收标准

- 页面能在微信小程序环境运行，没有明显构建、语法、类型或资源错误。
- 代码没有复制设计工具的绝对定位骨架、导出 DOM 或固定层级。
- 背景、顶部区域、模块边界、卡片、Tab、按钮、列表、文字、图标、图片裁剪和主要间距与设计证据一致。
- `src/pages.json` 中目标页面的 `navigationBarTitleText` 必须与设计标题或页面内自定义标题一致；使用自定义导航时必须配置 `navigationStyle: "custom"`，页面级 `backgroundColor` 必须与设计页面底色一致。
- 关键尺寸、样式、间距和状态已逐项验证；不能验证的项必须逐项说明。
- 设计切图已经通过 `scripts/upload-image-to-oss.cjs` 上传到 OSS，代码引用脚本输出的 OSS 地址，没有临时远程设计资源、本地下载切图路径或占位资源。
- 改动范围聚焦在还原目标，没有引入无关业务变化或额外视觉风格。
- 最低验证必须包含：`npm run build:mp-weixin`、页面配置检查、OSS 上传结果检查、新增切图引用检查、无远程设计资源检查、代码与规格账本逐项核对、微信小程序 E2E 自动化截图收尾返查；修改完成后运行 `graphify update .`。截图返查必须发生在代码实现和静态核对之后；如果微信小程序 E2E 自动化截图无法执行，必须说明具体阻塞原因，并提供可复现的手动小程序验收步骤；H5 截图只能作为风险辅助证据。

## 微信小程序截图能力

微信小程序截图不需要设计读取能力配合；设计读取能力只负责提供设计规格、截图和资源。小程序截图是工作结束前的收尾验证能力，用于确认已实现代码在真实小程序环境中的呈现，不用于替代设计规格、代码静态核对或项目 token 映射。小程序视觉验证需要的是微信开发者工具自动化能力：能打开构建后的 `mp-weixin` 产物、进入目标页面、等待页面稳定、截图、必要时读取页面状态和关键资源加载状态。

还原任务应复用仓库现有小程序 E2E 脚手架、登录态注入、路由 helper 和截图 helper。截图前必须已经完成代码实现、页面配置核对、资源引用核对和规格账本核对；截图必须生成有效图片文件并打开复查；只读到页面路由、元素或文本，不能替代截图返查。截图失败时先按“E2E 构建产物、自动化端口、登录态、路由进入、关键元素等待、截图落盘”拆分定位，并在关闭/重开自动化会话后重试一次；只有重试后仍失败，才可以降级为构建检查、静态规格核对、H5 辅助截图和人工可复现的小程序预览说明。交付时必须说明未完成小程序截图比对的具体原因和相关风险。
