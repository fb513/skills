# 工作流程

## 1. 使用 `prd-spec-iteration` 这个 skill 初始化新需求

## 2. 讨论需求并生成或修改原型

这一阶段由产品和 Agent 自由讨论：聊需求、调整 HTML 原型、推翻重来，工具不限。

唯一的硬要求是记账。上下文会压缩，不记就丢了。

### 记账规则

对话里出现明确的决定、否决、约束、范围外，或带倾向但还没收敛的表态，**当时在场的 Agent** 立即追加一条到当前需求目录的 `facts.md`，并告知编号（如「已记 L-007」）。

一行一条，`- L-001 已确认：原话`。三个要素，没有第四个：

| 要素 | 规则 |
|---|---|
| 编号 | `L-001` 起，本迭代内递增，不复用 |
| 状态 | `已确认` / `已否决` / `范围外` / `待定`，四选一 |
| 内容 | 原话，或按「转述判据」压缩过的转述；多人参与时标说话人，如 `（法务）`——不同来源的意见权重不同，不能混成一句 |

状态记的是**这句话是什么性质**，不是它落到哪个编号——`R-x`、`OS-x` 是生成阶段的去向，记账时不判。

| 状态 | 用在 | 例 |
|---|---|---|
| `已确认` | 正向结论 | `已确认：格式只给 CSV` |
| `已否决` | 明确不做，含被否掉的选项 | `已否决：不做批量删除，误删太吓人` |
| `范围外` | 属于本产品，但不归这一轮 | `范围外：导出进度条归 0003` |
| `待定` | 有倾向没收敛，或明确不知道 | `待定：上限先按 5 千，等法务回来` |

**先记倾向，再记收口。**「是否收口」要看全局，当轮判不准，判不准的结果就是漏记；「有没有出现倾向」只看这一轮。出现「要 / 不要 / 只 / 必须 / 不能 / 先 / 以后」这类标记词，就先记一条 `待定`，收口时再追加 `已确认` 覆盖。宁可一个话题两条，不要一条都没有。按话题记，不按句记：一句话里两个倾向拆成两条，同一话题的几句表态合成一条。没有标记词但带取舍态度的也算——「别搞得太花」「要让人一眼看懂」「跟 XX 那种感觉」这类品味型表述最容易被漏，而它决定了后面所有细节的取舍。

- **不加工成需求表述。**「想要个导出」不要写成「系统应支持导出功能」——后者是生成阶段的事，提前加工会让原话里的条件、让步、犹豫全部丢失
- **转述有判据。** 要压缩时保留四样：**条件**（如果 / 当 / 除非）、**具体数值与枚举**（5 千、CSV/XLSX）、**被否定项**（不要什么）、**强度词**（必须 / 应该 / 最好 / 可以 / 以后再说）；可以删语气词、重复和举例。强度词直接决定 `P1/P2`，压掉了优先级就只能靠猜。硬约束：转述不得引入原话里没有的名词——「导出」不能升级成「导出功能」「导出模块」
- **理由跟结论记在同一条。** 产品顺口给的原因是事实，和结论写一起，不单独拆行，也不要因为「不是决定」就丢掉
- **歧义要挂在账上，不要替产品解释。** 原话忠实不代表意图清楚：说「导出快一点」，快的是绝对耗时，还是要有进度反馈？记账时不做判断，追加一条 `待定` 把问题记下，生成时必然被拷问。原话那条保持不动
- **「以最后一条为准」只管取值。** 理由和替代方案要顺着 `收口 / 更正 / 补充` 指回的编号往回读——产品改主意通常是因为约束变了，只留最新值等于把原因删了，`DEC-xx` 也就写不出来
- **不分类、不判去向。** 不写「这是决策」「这是约束」，不写它属于 `R-x` 还是 `OS-x`
- **拿不准就写 `待定`。** 事后把待定改成已确认，成本远低于事后补漏
- **append-only。** 不删不改。三种追加：收口（`待定` → `已确认`，写「收口 L-00x」）、更正（结论反了，写「更正 L-00x」）、补充（同一主题加条件，写「补充 L-00x」）。同一主题以最后一条为准——记录顺序本身就是演进记录。被收口或被更正的 `待定` 不再是待定，不要让它在生成时变成 `Q-x`
- **只记本迭代说的话，不复制基准的事实。** 编号也只在本迭代内递增，不为对齐基准而跳号

不该记的：原型里长什么样（文件本身就是记录，生成时直接读）、纯背景闲聊、连倾向都没有的探索。

本轮与基准的关系通常开目录时已问定、写进 `manifest.yaml`，不用再记。两种例外各记一条：当时答「还不确定」现在有结论了；结论和原来的答案反了。生成时会把冲突列出来让人裁决，不会自己改。

**归属。** `facts.md` 是事实的唯一来源，`prd.md`、`spec.md` 是可再生派生物——事实有误时改事实记录并重新生成，不要直接改文档来修事实。只有记账能写 `facts.md`，其他 Skill 不得整理、补全、去重。

### 原型

**在当前需求目录里，就在那份上改。** 不要动其他需求目录的 `prototype.html`——那是那一轮的冻结件，改一个字节它的哈希就对不上了，而历史目录不可改写。

这一阶段没有结束标志，产品随时可以说「生成 PRD」进入下一步。

## 3. 使用 `prd-spec` 这个 skill 生成 PRD / Spec

产品说「生成 PRD」时进入这一步，产出 PRD、Spec 与变更摘要。

## 约定

- **目录与编号不复用。** 需求目录（如 `0001-订单批量导出/`）一经写入不覆盖、不改写。
- **产品文档不写实现。** PRD、Spec、`facts.md` 不含技术栈、API、数据模型、测试用例和开发缺陷。
