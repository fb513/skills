# PRD / Spec 迭代初始化器

负责创建本次需求的需求目录，并问清这次是历史需求的调整还是一个全新的需求（据此决定要不要把原型复制一份过来）。这个判断由人做，本 Skill 只负责把问题问清楚、给出有依据的建议。

## 具体工作

### A. 项目级（幂等）

1. 检查工作区根目录 `AGENTS.md`：
   - **不存在** → 按 [`references/agents-template.md`](references/agents-template.md) 实例化。
   - **已存在** → 校验两件事：文件可读、含「流程」标题。不重写、不重排；需要记东西就在需求目录表末尾追加（第 9 步）。
2. 校验失败或文件损坏时报告并停止，不自行重建——重建会把团队写进去的约定冲掉。

### B. 需求级（新建）

**本 Skill 只负责开新一轮，不在已有目录上改，也不判断已有文档处于什么状态。** 

3. **确定名称**：从产品这次的话里提取，例如「做订单批量导出」→ `订单批量导出`。提取不到时问一句「这一轮需求叫什么名字？」，不要猜，不要用 `untitled`。
4. **确定编号**：glob `[0-9][0-9][0-9][0-9]-*`，按数字取最大值 +1；一个都没有则为 `0001`。算出的编号已有同号目录时说明扫描不完整，报告并停止，不要凑出第二个同号目录。
5. **问清楚这一轮是什么。先问，再建目录**——有更小编号目录时问一句，把基准直接写进句子里：

   > 这一轮是一条全新的需求，还是在 `0002-题库管理` 上调整？

   **句子里填编号最大的那一轮**，绝大多数情况就是它。这次的话里点名了别的轮次（「在 0001 上改」「沿用题库那版」）时，换成被点名的那一轮。

   | 回答 | 需求目录表的「基于」列 | 接下来 |
   |---|---|---|
   | 全新的需求 | `—` | 建目录，不复制原型 |
   | 在某一轮上调整（含产品把句子里的编号改成别的） | 那一轮的编号 | 建目录，从该轮复制原型 |
   | 还没定 | — | **不建目录**，说明原因后结束 |

   **答「还没定」就停在这里，一个目录都不建。** 告诉产品「等定了是新的、还是在哪一轮上改，再来开这一轮」——不是拒绝，是省掉一次返工。

   | 听到的说法 | 建议 | 依据 |
   |---|---|---|
   | 改 / 加 / 调整 / 在原来基础上 / 沿用 / 基于某一轮 | 像调整 | 指向已有范围 |
   | 全新 / 独立 / 另一条线 / 跟哪个都没关系 / 只复用登录 | 像全新 | 明确不继承范围 |
   | 只给了一个功能名（如「做订单批量导出」） | 无法建议 | 没有参照，说不出依据就不猜 |

   建议不采纳也不影响流程：「基于」以人的回答为准，写进表就不再变。

   编号最大只是提问时的默认值，落不落进 `AGENTS.md` 的需求目录表要过这一句确认：回答「对，改一下」，那一行的「基于」就填句子里这个编号；产品改成别的，按改的写。

   没有基准目录时（首轮）必然是 `independent`，不用问——但要说一句「这是首轮，没有基准可选」，别默默当成新需求往下走。判断可以自己下，结论要让人看见。

6. 创建 `<编号>-<名称>/` 目录。走到这一步说明答案已经落定，不会是「还没定」。
7. **`derive` 时复制原型**。基准目录里有 `prototype.html` 就整份复制进来，没有就跳过、报告里说明。

   - **只看基准目录里有没有这个文件，不看 `ref`。** 每一轮的原型都在自己目录里，所以基准那份一定就在它自己的目录里；`ref` 在这里用不上，它的作用是表达「本目录没有文件」，那是生成阶段才判断的事
   - 早期目录可能没有 `ref` 字段，文件照样在，别因为字段没填就当成没有原型
   - 复制过去就叫 `prototype.html`，位置不用记——有没有原型只看文件在不在。**只碰基准的原型文件，不读它的 `prd.md` / `spec.md`。**

   为什么放在这一步：讨论期要改原型，总得有一份能改的。没有副本，产品要么去改基准目录（破坏它的不可改写约定），要么在临时文件里改到找不回来。复制是安全方向——多一份无害，少一份只有两种坏结局。
8. 写入空 `facts.md`：只有标题 `# 事实记录`，零条目。格式与写法见 `AGENTS.md`，此处不内联第二份。
9. **在 `AGENTS.md` 的「需求目录」表末尾追加一行**：编号、名称、基于（`—` 或四位编号）、简介（取产品描述这一轮的那句话，20 字以内，别加工成需求表述）。表还在就只加行，没有这一节就按 [`references/agents-template.md`](references/agents-template.md) 补上。**文件里其他内容一个字节都不动。**
10. 写入 `change-summary.md` 占位。

### 名称规则

- 直接用中文，不做拼音或 kebab-case 转换。编号前缀已保证唯一。
- 文件系统非法字符 `/ \ : * ? " < > |` 替换为 `-`；去掉首尾空格，连续空格压成一个。
- 20 字以内，过长取前 20 字并在报告里说明截断。

### 报告

```
工作区规则：新建 AGENTS.md
本轮需求：0003-订单批量导出（基准 0002，derive）
原型：已从 0002 复制
```

原型一栏据实写：`已从 0002 复制` / `未复制（独立需求）` / `未复制（0002 没有原型）`。首轮写 `本轮需求：0001-订单批量导出（首轮）`，没有基准也没有原型可复制。

答「还没定」时没有这份报告——目录没建，只说明一句「这一轮是新的还是在某轮上改还没定，定了再来开」。

基准不是编号最大的那一轮时，在「本轮需求」行注明 `非最新一轮`——否则看报告的人会默认你基于最新一轮改的，而这一轮其实是接在更早那一轮上。

## 目录结构

```text
<workspace>/
  AGENTS.md
  0001-订单批量导出/
    facts.md                # 事实流水账，append-only
    change-summary.md       # 变化 + 落点表 + 未变更项
    prototype.html          # derive 时从基准复制，讨论期在这份上改
    prd.md                  # 生成时写入
    spec.md                 # 生成时写入
  0002-导出历史与失败重试/
    facts.md
    ...
```

`facts.md` 在需求目录内，不在工作区根目录。跨迭代延续靠上一轮的 PRD，不靠事实原文。

## 编号规则

- 四位补零：`0001`、`0002`…`0010`。
- 目录名 `<四位编号>-<中文需求名称>`，中间用半角连字符。
- 编号与名称一经创建都不改写。名称要改就改 PRD 标题，目录不动。
- 已存在的需求目录不覆盖、不改写。编号永不复用。
- 基准迭代由 `AGENTS.md`「需求目录」表的「基于」列指定，见第 5 步。该列是 `—` 或整行缺失时，才算独立需求；行缺失且存在更小编号目录时，回落到「小于当前编号的最大已存在目录」。`0001` 没有基准。

## `AGENTS.md`

- **写流程、约定、记账规则和需求目录表**，不写 PRD/Spec 的章节骨架与生成方法——那些随 Skill 版本走，放进来只会两边漂移。
- **记账规则只在这里有一份**，含行格式。它必须在产品没调用任何 Skill 的讨论期生效，而 Skill 的 `references/` 那时读不到。其他 Skill 引用它，不复制它。
- **需求目录表**：「编号 / 名称 / 基于 / 简介」四列，是本工作区所有轮次的索引，也是基准关系的唯一来源。`derive` 还是 `independent` 不看别的字段——「基于」列有编号就是 `derive`，是 `—` 就是 `independent`。
- **追加式改动**。需要写的时候只在需求目录表末尾加一行，不重排、不改已有内容——重排会让 diff 变成一片红，谁也看不出到底动了什么。团队追加的规则优先于 Skill 默认行为。
- **步骤编号稳定**。新增步骤追加到流程末尾，不改已有步骤的编号和内容。

## 原型怎么记

不记。`prototype.html` 是固定文件名，有没有原型只看文件在不在；是哪一版交给 git——生成 PRD 后提交一次，commit message 写轮次编号，比在某个字段里存哈希完整得多。

## 输出约束

- UTF-8 编码，目录名使用中文。
- 不写产品内容，不判断范围、优先级或验收标准。第 5 步问的是目录之间的关系，不是产品需求。
- 答「还没定」时不建目录、不写任何占位文件。宁可不留痕，也不留一个说不清来历的空目录。
- 不覆盖任何已存在的需求目录。重复运行时给两个选项，不替产品判断该选哪个：接着改同一份就回原目录跑 `prd-spec`，要留档就继续开新一轮。
- 复制原型时整份复制，不改名、不裁剪、不替换内容；基准目录一个字节都不动。
- 对 `AGENTS.md` 只追加需求目录表的一行；表头、已有行、其他章节不动。重排会毁掉 diff，改了哪里就看不出来了。
