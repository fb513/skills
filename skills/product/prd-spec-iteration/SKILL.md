# PRD / Spec 迭代初始化器

负责创建本次需求的需求目录、并负责确认本次需求是历史需求的调整还是一个全新的需求（据此决定要不要把原型复制一份过来）。

## 具体工作

### A. 项目级（幂等）

1. 检查工作区根目录 `AGENTS.md`：
   - **不存在** → 按 [`references/agents-template.md`](references/agents-template.md) 实例化。
   - **已存在** → 只校验两件事：文件可读、含「流程」标题。**不读内容、不改写、不重排**。
2. 校验失败或文件损坏时报告并停止，不自行重建——该文件归产品团队所有。

### B. 需求级（新建）

**开目录前先确认**：产品这次要改的如果就是已有的某个需求、而且还没定稿，不要建目录——告诉它直接在那个目录里用 `prd-spec` 重跑即可。已定稿的才作为新的一轮。本 Skill 只负责开新一轮，不负责在原目录上改。

定稿没有字段标记，按这条判断：目录里已有 `prd.md`，且产品说这一版已经交付、或开发正按它在做，就算定稿。拿不准就问一句「这一轮是接着 0002 改，还是留档开新的一轮？」

3. **确定名称**：从产品这次的话里提取，例如「做订单批量导出」→ `订单批量导出`。提取不到时问一句「这一轮需求叫什么名字？」，不要猜，不要用 `untitled`。
4. **确定编号**：glob `[0-9][0-9][0-9][0-9]-*`，按数字取最大值 +1；一个都没有则为 `0001`。算出的编号已有同号目录时说明扫描不完整，报告并停止，不要凑出第二个同号目录。
5. 创建 `<编号>-<名称>/` 目录。
6. **确认本轮与基准的关系**。有更小编号目录时问一句：

   > 这一轮是在 `0002-题库管理` 的基础上改，还是一条独立的新需求？

   | 回答 | `relation` | 原型 |
   |---|---|---|
   | 在基准上改 | `derive` | 复制成新目录的 `prototype.html` |
   | 独立的新需求 | `independent` | 不复制 |
   | 还不确定 | `null` | 不复制，留给 `prd-spec` 判定 |

   找来源的顺序，取第一个命中的：

   1. 基准 `manifest.yaml` 的 `prototype.ref` 有值 → 顺着它找（可能就在基准目录，也可能指向更早的目录）
   2. `ref` 为 `null` 或字段不存在，但基准目录里有 `prototype.html` → **就用它**。这是最常见的情况：`0001` 生成时还没有 `ref` 这个概念，文件就在那儿
   3. 都没有 → 跳过，报告里说明

   复制成新目录的 `prototype.html`，并把 `manifest.yaml` 的 `prototype.ref` 写成 `./prototype.html`。判断只看**文件在不在**，不看 `ref` 有没有值——`ref` 的作用是表达「文件不在本目录」，文件在本目录时它就是 `./prototype.html`，没什么可表达的。**只碰基准的原型文件，不读它的 `prd.md` / `spec.md`。**

   没有基准目录时直接是 `independent`，不问。

   为什么放在这一步：讨论期要改原型，总得有一份能改的。没有副本，产品要么去改基准目录（破坏冻结），要么在临时文件里改到找不回来。复制是安全方向——多一份无害，少一份只有两种坏结局。
7. 写入空 `facts.md`：只有标题 `# 事实记录`，零条目。格式与写法见 `AGENTS.md`，此处不内联第二份。
8. 写入 `manifest.yaml`：`relation` 填第 6 步的答案（未确定则 `null`）；第 6 步复制了原型时 `prototype.ref` 填 `./prototype.html`，否则留 `null`；`prototype.sha256` 留 `null`，由 `prd-spec` 生成时算。
9. 写入 `change-summary.md` 占位。

### 名称规则

- 直接用中文，不做拼音或 kebab-case 转换。编号前缀已保证唯一。
- 文件系统非法字符 `/ \ : * ? " < > |` 替换为 `-`；去掉首尾空格，连续空格压成一个。
- 20 字以内，过长取前 20 字并在报告里说明截断。

### 报告

```
工作区规则：新建 AGENTS.md
本轮需求：0003-订单批量导出（基准 0002，derive）
原型：已从 0002 复制
```

原型一栏据实写：`已从 0002 复制` / `未复制（独立需求）` / `未复制（0002 没有原型）` / `未复制（关系待定）`。首轮写 `本轮需求：0001-订单批量导出（首轮）`，没有基准也没有原型可复制。

## 目录结构

```text
<workspace>/
  AGENTS.md
  0001-订单批量导出/
    facts.md                # 事实流水账，append-only
    manifest.yaml           # relation / prototype
    change-summary.md       # 变化 + 落点表 + 未变更项
    prototype.html          # derive 时从基准复制，讨论期在这份上改
    prd.md                  # 生成时写入
    spec.md                 # 生成时写入
  0002-导出历史与失败重试/
    facts.md
    ...
```

`facts.md` 在需求目录内，不在工作区根目录。跨迭代延续靠上一轮的 PRD，不靠事实原文。

## 编号规则

- 四位补零：`0001`、`0002`…`0010`。
- 目录名 `<四位编号>-<中文需求名称>`，中间用半角连字符。
- 编号与名称一经创建都不改写。名称要改就改 PRD 标题，目录不动。
- 已存在的需求目录不覆盖、不改写。编号永不复用。
- 基准迭代 = 小于当前编号的最大已存在目录。`0001` 没有基准。

## `AGENTS.md`

- **写流程、约定和记账规则**，不写 PRD/Spec 的章节骨架与生成方法——那些随 Skill 版本走，放进来只会两边漂移。
- **记账规则只在这里有一份**，含行格式。它必须在产品没调用任何 Skill 的讨论期生效，而 Skill 的 `references/` 那时读不到。其他 Skill 引用它，不复制它。
- **人工拥有**。创建后归产品团队。之后只校验存在性，不重写、不重排。团队在「团队约定」里追加的规则优先于 Skill 默认行为。
- **步骤编号稳定**。新增步骤追加到流程末尾，不改已有步骤的编号和内容。

## `manifest.yaml`

只存推导不出来的值：

```yaml
relation: null
prototype:
  ref: null
  sha256: null
```

`relation` 和 `prototype.ref` 是本文件里仅有的两个无法从别处反推的值，也是本 Skill 创建时会写的两个字段——前者要等第 6 步的答案（未确定则 `null`），后者只在复制了原型时写 `./prototype.html`。`sha256` 由文件算出，留给 `prd-spec`。

不存 `iteration`（目录名前四位有）、`feature`（连字符之后就是）、文件名（固定约定）、`base_iteration`（可推导）。

产品答「还不确定」时留 `null`，不追问。这一轮是独立需求还是上一轮的演进，有时候要聊几句才清楚，`prd-spec` 生成前会补判。

字段说明见 [`references/manifest-schema.md`](references/manifest-schema.md)。

## 输出约束

- UTF-8 编码，目录名使用中文。
- 不写产品内容，不判断范围、优先级或验收标准。第 6 步问的是目录之间的关系，不是产品需求。
- 不覆盖任何已存在的需求目录；重复运行时提示继续使用现有需求或确认是否开新一轮。
- 复制原型时整份复制，不改名、不裁剪、不替换内容；基准目录一个字节都不动。
